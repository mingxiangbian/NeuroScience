## Anti-Patterns Verdict

**LLM assessment:** 不像通用 AI 模板。真实脑模型、Cyber Ink 米纸、双弧身份和仪器化 display 形成了清楚的个人研究工作区风格。主要风险不是“AI 味”，而是展开态把多个好想法同时开到相近权重，导致视觉噪声高于信息增益。

**Deterministic scan:** `index.html` 共 12 条：8 条字体 warning、4 条色值 advisory。字体项把 `Songti SC` 与 `SFMono-Regular` 的大小写规范化误判为 DESIGN.md 之外字体，属于假阳性；4 个 rgba 是现有纸张明暗/透明度层级，属于有意 tonal values。没有检测到阻断性反模式。

**Visual overlays:** 当前浏览器控制面只提供只读 evaluate，无法可靠注入 detector overlay，因此没有声称存在用户可见覆盖层；使用 CLI detector、真实截图、DOM 几何和控制台日志作为替代证据。

## Overall Impression

折叠首屏已经很有记忆点：不像普通导航页，更像一台会呼吸的神经科学观测仪。最大的机会不是删掉动态，而是让展开后的动态层级更有“主奏与伴奏”：当前所有装饰都在，但重要的 connectome、Atlas 聚焦反而不够读得出来，PCB 灰板和重复模块框却更抢眼。

## What's Working

1. **折叠态构图成熟。** 1280 桌面与 390 手机上，大脑是唯一明确主角，六个 display 成为轨道节点，标题与双弧形成稳定品牌框架。
2. **搜索层很完整。** 背景模糊、纸面 dialog、输入焦点和信息层级都安静清楚，切断复杂 3D 背景后提供了高效率路径。
3. **动态身份不是通用特效。** 大脑旋转、双弧、脑沟色流与知识模块映射共同服务“Neural Observatory”，而不是随意粒子背景。

## Priority Issues

### [P2] 展开态缺少明确焦点

**Why it matters:** 展开后同时看到中央透明脑、六个外部 display、六个 DOM 模块标签、PCB、HUD 与连接线。用户仍能导航，但需要先判断哪一套模块表示才是主要操作层。

**Fix:** 保留全部层，但建立主从：DOM 标签保持主交互；未激活外部 display 降低约 35–45% 对比；脑体展开后的最低不透明度提高，让轮廓连续；HUD 与 active path 才使用最高局部对比。

**Suggested command:** `$impeccable polish`

### [P2] PCB substrate 是一个过重的灰色矩形

**Why it matters:** 桌面、手机和 portrait 中，脑下方的灰板都形成大块无语义重量，压住了大脑的有机轮廓，也比新增 connectome 更先被看见。

**Fix:** 不删除 PCB；把实体板降为约当前 45–60% 的视觉重量，使用纸面 tint、局部边框、插槽或走线密度表达“基座”，避免完整不透明矩形。

**Suggested command:** `$impeccable quieter`

### [P2] 新增 Observatory 信号太淡，装饰投入没有形成清晰回报

**Why it matters:** 双弧在折叠态提供了轮廓，但 active connectome 与单向 pulse 在真实截图中很难辨认；Atlas HUD 字号偏小且离 active 标签较远。用户想要的可视化存在于代码里，却不够存在于视觉里。

**Fix:** 只提升 active 状态：活动的 3–5 条 filament 增加线宽/不透明度，pulse 加短尾迹；HUD 提升一级字号并加一根细 leader line 指回投影脑区。idle 网络继续保持稀疏。

**Suggested command:** `$impeccable bolder`

### [P2] 手机展开态左侧模块框越出画面

**Why it matters:** 390×844 实测 association、sources、papers 的框从 `x=-29px` 开始。页面没有水平滚动，但框体被裁切，视觉上像响应式布局未完成。

**Fix:** 将左右标签 clamp 在 8–12px 安全区内，用短 leader line 或向脑侧偏移维持轨道关系；不要通过缩小文字解决。

**Suggested command:** `$impeccable adapt`

### [P1] 折叠态没有键盘等价入口，鼠标操作发现性也不足

**Why it matters:** 折叠首屏把六个模块按钮设为 `tabIndex=-1`、隐藏 Search，canvas 又是 `aria-hidden`。键盘用户无法进入主要导航；鼠标首次访问者也没有明确说明点击/拖动大脑，可能把它当成纯动画封面。

**Fix:** 增加一个与画面融合但语义真实的 `EXPLORE BRAIN / 展开研究空间` 按钮，并保留极轻的 `DRAG TO OBSERVE · TAP TO EXPAND` 仪器提示；首次交互后提示可淡出，但键盘按钮始终可达。

**Suggested command:** `$impeccable harden`

## Persona Red Flags

**Jordan（首次访问者）:** 进入折叠态后只看到大脑和六块 display，不知道点击脑会展开，也不知道搜索要在展开后出现；可能错过真正导航。

**Sam（键盘/低视力用户）:** 折叠态隐藏按钮已正确移出 Tab 顺序，但 canvas 本身 `aria-hidden`，键盘用户没有等价的“展开大脑”入口。展开后模块按钮可用，但 Atlas HUD 是装饰性隐藏，语义映射只能从按钮副标题获得。

**Casey（手机用户）:** 390px 展开态左侧三项被裁切；12 个模块视觉表示和大脑同时出现，单手用户需要更明确的主操作层。触控高度 44px 合格。

## Minor Observations

- active 外部 display 的长标题有接近截断的情况，例如 Association Cortex；建议统一动态字号缩放或两行安全区。
- 搜索 dialog 视觉完成度高，但空状态区域略高，可以在不改变尺寸的前提下增加最近入口或键盘提示。
- portrait 768×1024 比手机展开态稳定，左右标签、顶部/底部 display 和中心脑的关系清楚。
- 折叠动画终态很漂亮，但较长的过渡期间会短暂出现标签/Search 半透明残影；如果这是刻意的交接，需要让节奏更同步。

## Questions to Consider

- 展开态中，真正应该被第一眼操作的是 DOM 模块标签，还是外部 3D display？现在两者权重接近。
- PCB 是“计算基座”的关键叙事元素，还是应该退成只在 active module 时显现的支撑层？
- 如果只能强化一个新增效果，是 active connectome 的脑区到 display 路径，还是 Atlas HUD 的仪器感？
