# 投资学习阅读器（Finance Learning Reader）设计

- 日期：2026-07-13
- 状态：初版与「古金纸墨」改进均已实现并通过桌面、390px、320px、亮色与暗色验证
- 位置：`projects/finance/`
- 项目类型：knowledge / learning（按 `docs/project-creation-workflow.md` 路由）

## 背景与目标

`projects/finance/` 目前只有一份 42KB 的《投资入门详细教程》（`investment_beginner_guide_zh.md`，23 节，含 12 周学习计划、记录模板与术语表）。用户要在整个学习工作区下为投资学习建立一个子项目页，要求：记录学习内容、提升学习效率、便于沉淀成知识库供后续查阅。

用户确认的两个学习效率优先级：

1. **再入性（re-entry）**：打开页面立刻知道学到哪、下一步做什么。
2. **沉淀查阅（retrieval）**：术语、概念随时能检索到。

两者均由 Foundations 阅读器的既有机制覆盖（进度 + Overview 仪表盘；全文搜索 + 模块化），不新增机制。

## 初版自检与改进目标

初版完成后，结合桌面、390px、320px 和夜间模式实测，确认以下问题需要在本轮修复：

| 优先级 | 问题 | 验收信号 |
| --- | --- | --- |

## 视觉方向：古金纸墨

### 使用场景

用户在白天或室内普通光线下长时间阅读投资材料，需要快速恢复学习位置，同时避免高饱和金色、黑金奢侈品风格和亮黄色背景造成视觉疲劳。

### 色彩策略

采用 **Restrained（克制型）** 产品配色：中性米纸和深墨承担约 90% 的视觉重量，古金只用于当前状态、进度、焦点与关键行动。页面不使用可见绿色背景；绿色仅保留给未来明确的“已完成/成功”语义。

亮色主题角色：

- 主文字：`oklch(24% 0.018 72)`，深墨棕黑。
- 次级文字：`oklch(43% 0.025 75)`，需通过 4.5:1 正文对比度验证。
- 页面底色：`oklch(96% 0.012 92)`，保留研究工作区的米纸感，但不做通篇黄色铺底。
- 强表面：`oklch(98% 0.006 92)`，用于正文、工具栏和笔记表面。
- 古金文字：`oklch(42% 0.085 78)`，用于小标签、链接和当前状态。
- 古金图形：`oklch(52% 0.11 80)`，用于进度环、选中标记和非文字图形。
- 淡金洗色：`oklch(91% 0.035 84)`，仅用于 hover、focus 和背景光晕。

暗色主题角色：

- 页面底色：`oklch(16% 0.015 75)`。
- 抬升表面：`oklch(20% 0.018 75)`。
- 主文字：`oklch(93% 0.012 88)`。
- 古金强调：`oklch(78% 0.11 83)`。

所有文字和交互边界在最终实现中使用浏览器计算色值复核：普通文字至少 4.5:1，大文字和图形至少 3:1。金色不作为唯一状态信号，继续配合文字、位置和 `aria-current`。

### 视觉应用

- 背景：中性米纸基底叠加低强度古金光晕，移除当前绿色径向光晕。
- 当前模块：使用古金标记、完整边框或淡金背景，不新增粗侧边装饰条。
- 进度：古金承担进度图形；未完成轨道保持中性墨灰。
- 工具栏与面板：保留阅读器轮廓，Finance 专属主题将模糊强度控制在 18px 以内；普通内容不叠加宽阴影。
- 夜间模式：炭黑纸面配柔和金色，不采用纯黑 + 高饱和亮金的奢侈品模板。

## 改进实现边界

- 新增 `projects/finance/finance-theme.css`，在共享阅读器 CSS 之后加载；所有选择器以 `body[data-page="finance-roadmap-reader"]` 为作用域。
- 不复制整份 Foundations 样式，不改变 Foundations 的配色；共享 JS 只接受与状态判断、空状态和无障碍有关的最小通用修复。
- Finance 的可见标题改为「学习总览」和「学习导航」；底层模块 id `overview` 保持不变，避免破坏路由。
- Finance 页面不展示重复的原始优先级字符串；原始数据仍保留，避免改变内容模型。
- 宽度 `<= 480px` 时工具栏重排为两行：导航与主题/笔记控制在第一行，搜索独占第二行；主要触控目标为 44px。
- 无知识笔记时，笔记面板显示：「进入任一概念模块底部的「知识笔记」，选中文字即可添加本地批注。批注只保存在当前浏览器。」
- 全部学习模块完成时，“下一步”显示「全部模块已完成」，不再回退到第一模块。
- Finance 与 Foundations 的构建器都以 `done` 表示完成；共享的“下一未完成模块”判断同步使用 `done`，不再使用数据模型中不存在的 `complete`。

## 内容模型

记录四类内容：

| 内容 | 载体 | 说明 |
| --- | --- | --- |
| 教程本体 | `roadmap/modules/*.md` | 现有指南拆分而来，概念为中心 |

## 页面与数据流

- 复用 Foundations 阅读器交互模式：全文搜索、折叠章节导航栏、本地批注、模块进度；视觉通过 Finance 专属主题层隔离。
- Overview 仪表盘内容：总进度、各模块进度、当前建议下一步（12 周计划当前周 + 下一个未完成模块）、术语速查入口。
- 数据流：`modules/*.md` → `scripts/build-roadmap-data.mjs` → `roadmap/roadmap-data.json` → `index.html` 阅读器加载。
- 页面标识使用 `data-page` 属性（如 `finance-roadmap-reader`），标题与返回链接遵循站点主题页规范（`投资 | NeuroScience x AI`、返回 `../index.html`）。
- 代码复用采用共享 Foundations reader 资源 + Finance 专属主题层。共享行为修复必须同时回归 Foundations，Finance 视觉覆盖不得泄漏到其他项目。
