# 话题情绪工作台使用手册

日期：2026-09-01。适用于本机 Phase C 网站，不包含外部金标泛化评价。

工作台对一份来源可追溯的文本快照运行冻结模型，展示六类标签的预测分布。它不能确认作者的真实情绪，也不能据此估计整个论坛的情绪或模型准确率。

## 启动和解锁

```sh
cd /Users/phoenix/Assistant/NeuroScience/projects/llm-forum-text-emotion-recognition/forum-topic-emotion-web

```

打开 [本地工作台](http://127.0.0.1:8787)。从本模块 `private/access-token` 文件读取访问令牌，粘贴到登录框。不要把令牌放进 URL、截图、Git 或外部服务。HTTP 会话使用 HttpOnly、SameSite Strict cookie；锁定工作台会清除当前浏览器的会话 cookie。

服务只接受本机回环连接，不要配置公网代理。启动 API 不会立即加载模型；任务进入推理阶段才会启动独立模型进程。网站依赖位于本模块 `.venv`，不能安装进冻结的 `phase-a-runtime` 环境。

若已有 dispatcher 或继承其锁的模型进程存活，第二个服务会拒绝启动。不要删除锁文件绕过检查。Ctrl-C 停止服务时，正在执行的任务按实际停止结果保留，不自动续跑；下一次启动确认旧进程已退出后，将遗留运行状态标为失败。

## 新建任务

填写可辨识的话题名称，选择来源和模式，再点击“创建并开始分析”。同一时刻只有一个重推理任务；最多有 8 个待处理任务。创建任务会保存真实输入并消耗本机计算资源；单纯切换统计视图不会重新推理。

### 内容来源

| 来源 | 必填内容 | 采样含义 |
| --- | --- | --- |
| 上传 | UTF-8 CSV、JSON 数组或 JSONL；默认文本字段 `text` | 每条上传记录是一个对象；文件 hash 与行号提供追溯 |
| Stack Overflow | 标签或检索词，UTC 起止日期，上限与对象类型 | 窗口内新建问题的队列，以及这些问题同窗口内的回答、评论；不是全站事件流 |
| Python Discussions | 已审核的 Python Help 分类；主题与帖子上限 | 固定 `discuss.python.org`、category 7，按主题创建时间降序取分类前缀；不运行关键词搜索，也不承诺完整日期窗口 |

上传最多 5 MiB、500 条，每条原文最多 64 KiB。可选 `id`、`url`、`created_at`；日期须含时区。标签列不参与评价。CSV 的文本列名可修改；JSONL 示例只需：

```json
{"text":"Your English technical-forum text","created_at":"2026-08-24T10:00:00Z"}
```

模型使用选定的原生字符串，不做大小写归一化、代码删除或 URL 清洗。不同来源对象即使文本相同，也保留为不同出现次数。采集上限、分页、排除项与停止原因见“采样合同与运行边界”。来源受限、字段缺失或预算超限会停止，不会换来源或改样本补齐。

Python Help 当前仅用于非商业本地研究原型。内容条目保留作者、原帖链接与 CC BY-NC-SA 3.0 许可链接；来源审核不授权商业使用或完整语料再发布。详见 [来源审核](/Users/phoenix/Assistant/NeuroScience/projects/llm-forum-text-emotion-recognition/forum-topic-emotion-web/docs/discourse-source-review.md)。

### 三种模式

| 模式 | 执行行为 | 如何解释失败与降级 |
| --- | --- | --- |
| M1 only | 只运行 RoBERTa；可记录假设路由是否触发 | 不等于完整 Router；M3 实际调用为零 |
| Research | 使用冻结 router 和 cutoff，按需运行 M3 | 必需的 M3 失败就停止，不回退、不对当前批次重新取 top-k |
| Demo | 使用同一 router，额外允许用户设置 M3 尝试上限 | 普通 M3 故障或预算耗尽可沿用该条 M1 输出，并明确标记降级 |

所有模式都对身份漂移、非法输出和资源超限硬停。Research 不继承 Demo 的小额调用预算，但仍受任务条数、时间和内存上限约束。训练域的 15% 是冻结运行点，不是每个新话题必须满足的调用比例。

M1/M3 组件缓存只存在于本任务子进程内，以精确输入 hash 和运行版本绑定；缓存命中不增加 forward 次数。失败的 M3 输出不作为成功 M3 缓存。当前 `audit_rate=0`，没有额外抽检调用。

## 读懂结果

顶部“本次快照”始终按真实对象计数。成功预测数和覆盖率一起看；失败、取消和尚未预测的对象都不是 neutral。

“预测标签分布”有两个独立开关：

- **内容条数 / Object-weighted**：每条真实来源内容权重为 1，相同文本多次出现会多次计数。
- **规范化文本组 / Unique-text**：按 NFKC、casefold 和空白压缩后的文本 hash 分组。每个有成功预测的组总权重为 1，组内成功出现均分该权重。不同预测取平均，不选择代表、不做 OR 合并，也不重新运行模型。这里的计数可以是小数。
- **标签出现率 / prevalence**：标签加权激活数除以有成功预测的统计单位数。多标签出现率相加可以超过 100%。
- **阳性标签构成 / positive share**：某标签加权激活数除以六类标签的加权总激活数。有阳性时总和为 100%；没有阳性时不可定义，显示“—”。这不是内容出现率。

Unique-text 的组覆盖率表示“至少有一次成功预测的组”占全部组的比例。一个组中仍可能有未完成对象，因此界面还显示组内缺失数；顶部对象覆盖率不会被组覆盖率替换。

日趋势使用来源发布时间的 UTC 日期；周趋势从 UTC 周一开始。每个日或周桶内部重新分组和分配权重。跨多个桶出现的同一文本可以在每个桶各贡献一次，因此各桶唯一组数不能直接相加作为全期唯一组数。缺日期的对象不进入趋势，没有内容的日期不补零。

“对象类型与路由分层”沿用当前权重和比例开关，分别显示每层成功/纳入单位及六标签比例。`true`、`false`、`unknown` 按已保存的实际 `route_requested` 分组；unknown 包括未取得路由决策的回执。每一层独立归组，跨层组数不能当作全局唯一组数相加。路由不是随机分配的，这些分层不能证明 M3 比 M1 更准确。

“未检出六标签”只表示六个阈值均未触发。Cardinality 是每个成功对象触发的标签数。M1 熵、阈值距和 token 截断是运行诊断，不是外域正确概率。

## 路由与成本

切换 Unique-text 不会改变成本：成本始终按真实对象回执和实际 forward 计数。

区分请求路由、假设路由、M3 实际尝试、成功、缓存命中、最终使用路径和降级。M1-only 的假设触发比例不是 M3 调用率。成对分歧只覆盖同时有 M1/M3 决策的子集。

若子进程返回了有效失败累计计数，工作台用累计覆盖成功回执计数，不把两者相加。运行中、被取消或强制终止且没有完整累计的任务，只能显示已回执成本的下界；未知调用不能写成零。具体字段见 [数据合同](/Users/phoenix/Assistant/NeuroScience/projects/llm-forum-text-emotion-recognition/forum-topic-emotion-web/docs/data-schema.md)。

## 导出、取消、重放和删除

- “导出 JSON”导出当前任务元数据与公开条目视图，不包含完整输入或来源原始 payload；可包含 280 字符预览和逐条预测，仍应作为私有研究数据处理。导出不会自动包含旧任务只读补算但未封存的 derived 视图。
- “逐条 CSV”导出出处、署名、hash、时间、六标签预测与调用计数，不含全文、预览、原始 payload 或 author_id_hash。缺失预测和未知计数保持空白，不补零。危险电子表格公式前缀会增加文本转义引号；CSV 中的来源链接沿用公开展示修正。明细到期后不再提供 CSV。
- “取消任务”撤销后续写入并停止该任务的子进程；已封存输入与已回执结果保留为取消任务。
- “重放此快照”会创建新任务、新进程和空缓存，不是免费重新展示。只能重放仍保留原输入的终态快照；失败任务不会自动重放。
- “清除全文”只允许终态任务，立即移除原文、来源原始内容、预览和可能遗留在 request 中的上传内容副本，保留元数据、预测、原 snapshot hash 与聚合。清除后不能重放；原 hash 仍表示曾封存的输入，不表示全文仍然存在。排队中及运行中的任务会拒绝此操作。
- “删除任务”先禁止读取和晚到写入，再等待该任务子进程退出并清除数据库记录。不要用删除掩盖正式实验失败；有保留要求的实验工件应遵守对应协议。

## 保留期与失效视图

保留期从任务创建时间计算，只对终态任务清理：

| 到期时间 | 清理内容 | 仍可用内容 |
| --- | --- | --- |
| 7 天 | 全文、原始 payload、文本预览 | 逐条元数据、预测、已封存聚合；不再允许输入快照重放 |
| 30 天 | 逐条记录与预测 | 已封存聚合直到 90 天 |
| 90 天 | 任务及聚合 | 无 |

默认聚合成功的新任务把 derived 一同封存，可在 30 天明细清除后继续展示到 90 天。旧任务不回填数据库：明细尚在时仅只读补算新视图；明细到期且未封存 derived 时，新增视图明确不可用。未到聚合阶段的失败或取消任务也不能被假定拥有完整 derived。

清理在服务启动、运行中的周期检查或手动调用清理接口时执行；服务关闭时不会自动清理。终态规则不意味着后台正在运行的任务会被按日数强行删掉。SQLite 的 secure-delete 与 WAL checkpoint 不等同于清除系统备份、已导出副本或 SSD 介质上的所有痕迹。

所有原文、数据库、令牌和本地验收工件位于 ignored `private/`。不要上传它们。若页面提示身份漂移或资源超限，保留错误码与安全诊断，停止该次运行，不修改冻结文件让检查通过。
