## 2. 研究背景与问题界定

论坛文本包含用户对事件、产品和他人的评价，也包含愤怒、失望、喜悦、恐惧等情绪信息。准确识别这些信息可服务于舆情分析、社区治理、客户支持和情绪感知人机交互。然而，论坛中的情绪并不总由明确的情绪词表达。反讽、否定、网络用语、回复关系和前文事件都可能改变一句话的情绪含义。

本项目需要区分三个不同问题：

1. **说话者如何产生情绪**：涉及第一人称体验、认知评价、生理活动和神经机制。
2. **观察者如何推断说话者的情绪**：观察者根据语言、情境和对话历史重建他人的状态。
3. **模型如何产生情绪标签**：模型从输入文本及上下文形成内部表征，再输出预定义标签。

论坛文本情感识别主要研究第二和第三个问题。数据集标签通常来自标注者对文本所表达或暗示情绪的判断，并不等同于作者完整、真实的主观体验。因此，本项目不宣称从语言模型中发现人类情绪产生的生物机制，而是研究大语言模型是否形成了类似观察者情绪推断所需的计算过程。

本项目将重点考察以下可能的推断链条：

```text
论坛情境与对话历史
  -> 说话者的语言表达
  -> 模型重建说话者的处境与认知评价
  -> 情绪判断及置信度
  -> 可选的回复策略
```

其中，认知评价（cognitive appraisal）可包括目标是否受阻、事件是否愉快、责任归属于谁、结果是否可控或确定等信息。

## 3. 国内外研究现状

### 3.1 从文本分类到上下文情绪识别

传统方法通常将情感识别建模为词袋、情感词典或统计分类问题。预训练语言模型出现后，BERT、RoBERTa 等编码器成为文本情绪分类的主要基线。TweetEval 提供统一的社交媒体分类评估流程，GoEmotions 则提供细粒度、多标签的 Reddit 评论数据。

会话情绪识别（Emotion Recognition in Conversation, ERC）进一步引入说话者、对话历史和情绪转移。DialogueGCN 等方法利用对话关系建模上下文，但论坛具有异步、多分支和长线程特点，不能直接等同于线性对话。

### 3.2 大语言模型情绪识别

InstructERC 将 ERC 重构为受约束的标签生成任务，并结合指令、对话历史、标签说明、检索示例和参数高效微调。该方法说明生成式大语言模型可以完成情绪分类，但多个组件同时变化时，最终分数不能直接说明模型依赖了哪一种信息，也不能说明模型是否形成了可解释的情绪推理过程。

因此，本项目将把 InstructERC 作为重要的 LLM 基线和复现对象，而不是把“生成标签”本身作为最终研究贡献。

### 3.3 认知评价与情绪推理

认知评价理论认为，不同情绪与个体对事件的目标相关性、责任、可控性、确定性等评价有关。已有文本研究表明，人类标注者和分类模型可以从事件描述中重建部分认知评价，联合建模 appraisal 也可能改善情绪分类。近期研究进一步把“根据情境推断他人情绪”视为一种情绪推理或情感 Theory of Mind 任务，并发现 LLM 在隐含情境与具体情绪的对应上仍存在困难。

这些工作为本项目提供了比单纯标签分类更深入的研究视角：模型是否先形成说话者处境或 appraisal 的中间表征，再据此输出情绪标签。

### 3.4 内部表征与机制分析

机制可解释性研究可通过分层探针、激活替换、消融和表征 steering，检验某类内部信息在模型的哪些层出现，以及它是否真正影响最终预测。Tak et al. 在开放权重自回归模型中发现，部分情绪与 appraisal 信息集中于中间层，并可通过因果干预改变情绪输出。

稀疏自编码器（Sparse Autoencoder, SAE）提供了另一种候选分析单位。SAE 使用稀疏瓶颈重构 Transformer 某一层的激活，并学习一个通常比原始神经元维度更大的特征字典。其动机是把单个神经元或激活方向中相互叠加的多种信息，分解为更稀疏、可能更容易解释的特征。研究者可根据高激活文本、最小对照样本和特征干预，为候选 SAE 特征提出语义解释。

对本项目而言，SAE 可用于比较显式情绪词、隐式情绪、上下文依赖和 appraisal 样本激活的特征是否不同，并寻找可能对应说话者状态、责任、确定性、威胁或目标受阻的候选特征。但 SAE 不会自动给出可靠机制解释：部分特征可能难以命名、错误合并或拆分概念，稀疏性与重构质量之间也存在权衡。只有当候选特征在未用于解释的样本上稳定响应，并且对其进行受控干预会选择性改变情绪预测时，才可提出较强结论。

Anthropic 的 J-space 研究使用 Jacobian lens 识别与潜在可报告概念相关的共享内部表征。相关实验表明，这些表征可参与部分多步推理，但简单 sentiment classification 在移除 J-space 后仍能基本运行。这提示情绪任务可能同时存在两类路径：

- 依赖显式情绪词或稳定模式的自动分类路径。
- 依赖上下文、说话者处境和中间概念的情绪推理路径。

J-space 在本项目中首先作为研究动机和方法参考。除非后续确实在开放权重模型上实现并验证 Jacobian lens，否则不把“复现 J-space”写成项目方法或成果。Anthropic 关于 emotion vectors 的研究同样只能说明模型内部存在具有功能作用的情绪相关表征，不能证明模型具有主观感受。

## 4. 研究目标

### 4.1 总体目标

在合规获得并可靠标注的论坛或社交媒体文本上，构建可复现的情感识别系统，比较传统机器学习、预训练编码器和大语言模型在准确性、稳健性、成本及上下文利用方面的差异，并进一步分析模型何时依赖表层语言线索、何时需要情境推理。

### 4.2 具体目标

1. 明确数据来源、标签体系、匿名化方式和评估协议。
2. 复现简单基线、预训练编码器基线和至少一种 LLM 方法。
3. 比较无上下文、父回复上下文和线程上下文设定。
4. 建立显式、隐式、上下文依赖、反讽和否定等分析子集。
5. 在开放权重模型上探索情绪及 appraisal 中间表征。
6. 通过受控干预检验相关表征是否影响最终情绪预测。
7. 在核心实验完成后，构建情绪感知回复演示，检验情绪判断的下游价值。

## 5. 研究问题

### RQ1. 不同模型路线的真实差异是什么？

在固定数据与评估条件下，TF-IDF、BERT/RoBERTa 和 LLM 方法在 Macro-F1、各类别表现、稳定性、成本和延迟方面有何差异？

### RQ2. 上下文的收益出现在哪里？

回复或线程上下文是否主要改善反讽、指代、否定和隐含情绪样本，而对具有明确情绪词的文本帮助有限或引入噪声？

### RQ3. 模型是否形成了可参与预测的中间情绪表征？

情绪、说话者状态和 appraisal 信息在模型的哪些层可被解码？这些信息只是与输出相关，还是会因果影响最终标签？

### RQ4. 机制分析能否带来实际收益？

基于 appraisal 的辅助监督、样本设计或表征干预，能否提高隐式和上下文依赖样本的鲁棒性、校准度或回复适切性，而不是只提高少量展示样例的表现？

## 6. 待验证命题

以下内容均为研究假设，不是当前结论：

1. 显式情绪样本可能主要依赖词汇和局部模式，未必需要复杂的共享中间表征。
2. 隐式或上下文依赖样本更可能要求模型重建说话者的目标、责任、可控性和事件结果。
3. 可解码的内部信息不等于模型真正使用了该信息；只有受控干预改变输出时，才能提出较强的因果主张。
4. 机制分析首先用于发现捷径和失败原因，不保证自动提高总体 Macro-F1。
5. appraisal-aware 方法的潜在收益更可能体现在困难子集、跨域稳健性、校准和回复策略，而不是所有样本的平均分。

项目的通用假设、反证条件和对应实验继续在 [`hypotheses.md`](hypotheses.md) 中追踪。

## 7. 研究内容与方法

### 7.1 数据与任务定义

- 首先使用 TweetEval 和 GoEmotions 验证训练与评估管线。
- 自建论坛数据的来源、许可、隐私和再分发方式需经导师确认后确定。
- 按 `thread_id` 划分训练集、验证集和测试集，避免同一线程跨集合泄漏。
- 先完成粗粒度单标签任务，再根据标注一致性决定是否扩展为细粒度多标签。
- 在测试集或人工审核子集中标记显式情绪词、上下文需求、反讽、否定和歧义类型。
- 如标注资源允许，增加少量 appraisal 维度，用于分析而非替代原始情绪标签。

### 7.2 可复现基线

- TF-IDF + Logistic Regression 作为简单 sanity baseline。
- BERT 或 RoBERTa 作为有竞争力的编码器基线。
- Zero-shot 和 few-shot LLM 作为生成式模型对照。
- InstructERC 作为上下文、检索示例和参数高效微调路线的参考。

所有方法使用同一数据版本、测试集和评估脚本，并保存配置、随机种子、训练日志和预测结果。

### 7.3 上下文与失败分析

比较以下输入设定：

1. 仅目标文本。
2. 目标文本加父回复。
3. 目标文本加回复路径或受长度限制的线程上下文。

除总体指标外，分别报告显式、隐式、上下文依赖、反讽、否定、网络用语、少数类和长文本子集的结果，避免总体平均值掩盖真实差异。

### 7.4 内部表征分析

机制分析只在开放权重模型上进行，候选方法包括：

- 使用 layer-wise linear probe 检查情绪、appraisal 和上下文依赖信息在不同层的可解码性。
- 使用最小对照样本改变责任、结果、确定性或目标一致性，同时尽量保持其余文本不变。
- 在探针定位候选模型层后，优先寻找与该模型和层兼容的预训练 SAE；如无合适资源，再评估是否在受控语料上训练小规模 SAE。
- 比较 SAE 特征在显式、隐式和上下文最小对照样本上的激活，并记录高激活样本、重构误差、平均稀疏度和无效特征比例。
- 使用 activation patching、ablation 或 steering 检验候选表征是否影响最终标签。
- 设置随机方向、无关概念和表层词汇控制，避免把一般扰动误认为情绪机制。
- 仅在资源和实现条件允许时尝试 J-lens，不将其设为最低交付要求。

线性探针只能说明信息可被读取，SAE 特征的高激活样本也只能支持语义假设，两者都不能单独证明模型依赖该信息。因果表述必须建立在受控干预、选择性检查和重复实验之上。模型内部机制与人类认知之间的相似性也只能在任务、表征或算法层讨论，不能据此推断共同的生物实现。

### 7.5 下游系统演示

演示系统首先输出：

- 预测情绪及置信度。
- 使用的上下文范围。
- 可选的 appraisal 或失败风险提示。
- 对不确定样本的澄清或人工复核建议。

在此基础上，可加入受约束的情绪感知回复策略，例如调整语气、请求澄清、缓和冲突或建议转人工。演示的目的不是让模型“具有情绪”，而是检验更可靠的用户状态估计是否改善回复适切性。

完整 Agent 的长期规划、工具调用和记忆策略不属于开题阶段的核心交付，可作为后续扩展。

## 8. 技术路线

```text
任务与合规边界确认
  -> 公开数据基线复现
  -> 论坛数据协议与线程级划分
  -> TF-IDF / RoBERTa / LLM 公平比较
  -> 无上下文与上下文对照
  -> 困难样本分组和失败分析
  -> 开放模型分层探针
  -> 一组受控因果干预
  -> 可选的 appraisal-aware 改进
  -> 情绪感知回复演示
  -> 论文、代码与证据归档
```

详细阶段、停止条件和通过标准见 [`research-roadmap.md`](research-roadmap.md)。

## 9. 评估方案

### 9.1 情绪识别

- Macro-F1。
- 各类别 precision、recall 和 F1。
- 混淆矩阵与类别支持数。
- 多随机种子波动或置信区间。
- 校准误差或可靠性曲线。
- 显式与隐式、无上下文与上下文子集结果。

Accuracy 和 Weighted-F1 只作为补充，不单独用于支撑结论。

### 9.2 机制分析

- 不同层的 probe 表现及其跨划分稳定性。
- 干预前后的标签概率、预测变化率和效应大小。
- 对目标情绪或 appraisal 的选择性。
- 随机方向、无关概念和词汇控制实验。
- 失败干预及不能支持的结论。

### 9.3 下游回复

- 回复与用户情绪及情境是否一致。
- 是否在不确定时合理请求澄清。
- 是否避免机械迎合、情绪镜像或不适当的积极回应。
- 固定策略、仅使用情绪标签和使用情绪加 appraisal 三种设定的对照。

如采用人工评价，需提前定义评价量表、盲评方式和一致性指标。

### 9.4 工程成本

- 模型版本、提示模板和解码参数。
- 训练或调用成本。
- 推理延迟与格式有效率。
- 硬件、环境、依赖版本和随机种子。

## 10. 预期创新点

1. 将论坛文本情感识别明确区分为表层情绪分类与上下文情绪推理。
2. 在总体指标之外，建立显式、隐式和上下文依赖的分组评估。
3. 从“模型输出了什么标签”推进到“哪些内部信息参与了判断”，并区分相关性与因果证据。
4. 探索 appraisal 表征能否帮助解释或改善困难样本。
5. 将情绪识别结果连接到受约束的回复策略，验证其实际交互价值。

以上均为预期贡献，最终只能根据完成的实验和可复核证据表述。

## 11. 可行性与范围控制

| 层级 | 内容 | 开题定位 |
| --- | --- | --- |
| Must | 数据协议、简单基线、编码器基线、LLM 对照、完整指标、失败分析和可运行演示 | 必须完成 |
| Should | 显式与隐式子集、分层探针和至少一组受控干预 | 研究深化 |
| Could | SAE、J-lens、appraisal-aware 训练、复杂 chatbot 评价或 Agent 扩展 | 资源允许后开展 |

主要风险及应对方式：

- **数据合规不明确**：先使用公开数据，未确认前不大规模采集或公开论坛原文。
- **标签一致性不足**：先做小规模双人标注，必要时降低标签粒度并保留 `unclear/other`。
- **机制实验计算量过大**：优先选择 1B 至 3B 级开放模型和受控子集。
- **探针结果被过度解释**：将 probe 与干预分开报告，不把可解码性写成模型实际使用。
- **SAE 特征被过度解释**：同时报告重构质量、稀疏度、无效特征和反例，不把自动命名或少量高激活样本当作机制证据。
- **复杂方法未超过基线**：保留完整负结果、控制实验和失败原因，不以隐藏实验换取漂亮指标。
- **范围持续扩大**：在核心系统和基线未通过前，不训练 SAE、不开展 J-lens 或完整 Agent。

## 12. 现实价值

本项目最直接的价值是提高论坛情绪识别系统在隐式表达和上下文依赖场景下的可靠性，并为结果提供可复核的失败解释。

对 chatbot 而言，情绪识别可以支持语气调整、澄清、冲突缓和和人工转接，但必须保留不确定性，避免根据单次预测对用户作出过强判断。对 Agent 而言，情绪可作为交互状态的一部分，影响后续规划和策略选择；这一价值需要通过任务完成、纠错、升级和交互质量等下游指标验证，不能只由情绪分类分数推出。

机制分析可能帮助发现模型依赖的捷径，并指导数据增强、辅助监督或表征干预，但可解释性本身不保证提高基础模型的平均性能。其更现实的收益可能表现为困难样本鲁棒性、校准、可控性和回复适切性的改善。

## 13. 伦理与合规

- 核查论坛平台条款、研究授权和数据再分发边界。
- 删除或哈希用户名等直接标识符，并评估正文能否重新识别作者。
- 公开数据说明、标签协议、删除机制和允许用途。
- 检查情绪标签中的文化、语言和群体偏差。
- 不把模型预测当作用户真实心理状态或临床判断。
- 在心理健康、危机识别等高风险场景中，只将系统作为辅助信号，并设置人工复核和升级机制。

## 14. 预期成果
