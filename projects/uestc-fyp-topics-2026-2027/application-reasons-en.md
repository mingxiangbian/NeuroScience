## #46 Gen-LEAP: Generative AI for Learning, Engagement, Adaptation, and Personalisation

I would like to apply for this project because it matches my current direction in applied artificial intelligence and LLM-based systems. I am studying Electronic Information Engineering in the UESTC and University of Glasgow dual-degree programme, and my academic interests have moved from traditional electronic engineering toward machine learning, intelligent systems, and practical AI applications. Gen-LEAP is attractive to me because it asks a concrete question: how can generative AI support learning in a way that adapts to different students, instead of offering the same static material to everyone?

Many learning platforms still treat students as if they have the same background, pace, and weak points. A generative AI learning assistant can do more. It can explain course material, identify possible gaps in understanding, recommend follow-up practice, generate short quizzes, and adapt explanations to the learner's level. I am interested in this project because a useful system would require more than connecting a chatbot to an interface. It would require task design, retrieval or prompt design, user modelling, evaluation, and careful engineering.

My previous coursework and projects give me a suitable foundation. I have studied Artificial Intelligence and Machine Learning, Signals and Systems, Linear Algebra, Calculus, Circuit Analysis, and Digital Logic. These courses trained me to connect mathematical models with implementable systems. In my SVD-based image compression project, I worked with numerical representation, reconstruction quality, and the trade-off between compression and information loss. In my NeRF-based 3D reconstruction work, I used PyTorch and saw how neural models learn hidden structure from data. In my NIPT statistical modelling project, I handled real-world data, model evaluation, and decision-making under uncertainty. These experiences taught me to move from a problem definition to a measurable result.

For this project, I would like to build a focused prototype rather than a broad learning platform with too many unfinished functions. One feasible direction is a retrieval-augmented learning assistant that organises course materials, answers student questions with source-grounded explanations, recommends practice based on previous mistakes, and generates short quizzes. The system could maintain a simple learner profile so that later responses reflect earlier performance. This workflow would give the project a clear user journey and a clear thesis structure.

I would also pay close attention to evaluation. A generative AI education system should not be judged only by fluency. I would test answer correctness, relevance to source materials, hallucination control, response consistency, and usefulness for different learner profiles. If possible, I would compare different prompting or retrieval strategies and analyse typical failure cases. This would help the project avoid the common weakness of AI demos that look impressive but provide little evidence of reliability.

This topic fits my longer-term plan to work in AI engineering, machine learning engineering, or LLM application development. A Gen-LEAP project would allow me to gain experience in model integration, system design, evaluation, and user-facing AI development. It would also produce a project that I can present in future graduate applications or job applications: the need is real, the system is concrete, and the technical work includes both AI methods and engineering decisions.

If selected, I would first clarify the expected application scenario, data sources, model constraints, and evaluation criteria. Then I would build a baseline system, identify its weaknesses, and improve it through retrieval design, prompt design, personalisation logic, or lightweight model adaptation. My goal would be to produce a working prototype, a reproducible experimental process, and a thesis that explains both the system and the evidence behind its effectiveness.

## #28 Human Activity Recognition using WiFi Channel State Information

I would like to apply for this project because it connects signal processing, machine learning, and intelligent sensing. These areas match my undergraduate background in Electronic Information Engineering and my current interest in applied AI. Human activity recognition using WiFi Channel State Information is an appealing topic because it uses ordinary wireless signals to infer human movement without relying on cameras. The project therefore combines technical depth with a practical privacy advantage.

Camera-based activity recognition can perform well, but it depends on lighting, viewpoint, and visual access. It also raises privacy concerns in indoor environments. WiFi CSI provides another sensing route. Human movement changes the wireless propagation environment, and CSI captures those changes as time-series signal patterns. A recognition system can then learn to classify activities such as walking, sitting, standing, or other indoor behaviours. I find this direction valuable because it shows how AI can extract useful information from signals already present in everyday environments.

My academic preparation fits the project well. I have studied Signals and Systems, Linear Algebra, Calculus, Circuit Analysis, and Artificial Intelligence and Machine Learning. These courses gave me the mathematical tools to understand signal behaviour, feature representation, and model training. In my SVD-based image compression project, I worked with signal and image representation, dimensionality reduction, and reconstruction quality. In my NIPT statistical modelling project, I handled real-world data and learned how data quality, preprocessing, and evaluation design affect model results. These experiences are relevant to CSI-based recognition, where raw signals may contain noise, environmental variation, and subject-dependent patterns.

For this project, I would like to build a complete and reproducible recognition pipeline. I would first study the CSI data format and preprocessing requirements. Depending on the dataset, I may need to handle missing values, reduce noise, segment activity windows, normalise signal amplitudes or phases, and construct time-series samples. After that, I would compare several models, such as classical machine learning classifiers, CNN-based time-series models, recurrent models, or lightweight Transformer-style models if they fit the data. I would not assume that the most complex model is the best. I would compare methods based on accuracy, robustness, computational cost, and generalisation across users or environments.

I also want the project to answer a technical question rather than only report a final accuracy number. For example, I could study how environmental changes affect recognition performance, which features contribute most to classification, or whether a simpler model with stronger preprocessing can compete with deeper models. If the data allows, I would compare within-subject and cross-subject performance, or same-environment and cross-environment performance. This would show whether the model has learned activity-related patterns rather than memorising details from one collection setup.

The project also fits my interest in intelligent systems that interact with the physical world. It sits between pure software AI and hardware-heavy engineering. I would still work with real physical signals and practical constraints, but I would not need to focus on PCB design or soldering. This balance suits my current strengths: programming, modelling, data analysis, and system evaluation.

If selected, I would first clarify whether the CSI dataset is provided or whether data collection is required. Then I would build a baseline pipeline, analyse the main sources of error, improve preprocessing and model design, and evaluate generalisation under different conditions. I would document the workflow so that the final thesis explains the model choice, the reasons it worked, the failure cases, and the limitations for practical WiFi-based sensing.

## #29 Deep learning-based Machine Health Monitoring Systems under Practical Operating Conditions

I would like to apply for this project because it combines deep learning, sensor data analysis, and engineering reliability. Machine health monitoring is a strong applied AI topic: the model should help detect abnormal conditions, reduce maintenance cost, and improve the reliability of industrial equipment. This direction fits my background in Electronic Information Engineering and my interest in machine learning systems that solve practical problems.

The phrase "under practical operating conditions" makes this project a strong fit for my interests. Many classroom models train and test on clean datasets under stable assumptions. Industrial monitoring is harder. Sensor signals may contain noise, machines may operate under different loads or speeds, faults may be rare, and the data distribution may change over time. These constraints make the project more realistic than a standard classification task. I want to work on this topic because it would train me to think about robustness, data quality, deployment constraints, and model accuracy as one connected problem.

My coursework and project experience provide a relevant foundation. I have taken Signals and Systems, Linear Algebra, Calculus, Circuit Analysis, and Artificial Intelligence and Machine Learning. These courses are relevant because machine health monitoring often uses vibration, current, acoustic, or other time-series signals. The models need both signal understanding and machine learning knowledge. In my NIPT modelling project, I worked with real-world data and used statistical methods to support decision-making. That project taught me how data imbalance, uncertainty, and evaluation metrics can change the meaning of a model result. In my SVD image compression project, I worked with representation and reconstruction, which strengthened my understanding of how information can be transformed and preserved.

For this project, I would like to build a pipeline that covers preprocessing, model training, evaluation, and practical-condition analysis. Depending on the available datasets, I would first study the sensor type, machine type, fault labels, and operating conditions. Then I would clean and segment the data, extract time-domain or frequency-domain features if needed, and build baseline models. I would compare classical machine learning methods with deep learning approaches such as CNN-based signal classifiers, recurrent models, or other suitable architectures. I would also examine false alarms, missed detections, model stability, and performance under different operating conditions.

The project has strong thesis potential because machine health monitoring in practical environments remains challenging. A model that performs well under one load or speed may fail under another. I would like to examine this issue through controlled experiments. For example, I could compare same-condition testing with cross-condition testing, or evaluate how noise and limited training data affect performance. If the project scope allows, I could explore transfer learning, domain adaptation, data augmentation, or lightweight models for resource-constrained deployment.

I would also pay attention to the cost of false decisions. A false alarm may waste maintenance resources, while a missed fault may lead to equipment damage or safety risks. For that reason, I would not report only overall accuracy. I would examine precision, recall, confusion matrices, and performance on minority fault classes. If the dataset has class imbalance, I would consider sampling strategies, class-weighted losses, or threshold adjustment. This would connect model output with real maintenance decisions.

This project matches my career direction in AI engineering and intelligent systems. Predictive maintenance appears in manufacturing, energy, transportation, and robotics, so the skills from this project would transfer to many industrial AI applications. The topic also suits my current preference because it focuses on modelling, software implementation, and evaluation rather than PCB design or soldering.

If selected, I would first clarify the dataset, machine type, fault categories, and evaluation requirements. Then I would reproduce a basic monitoring model, analyse its weaknesses, and improve the pipeline step by step. My goal would be a working machine health monitoring prototype or analysis framework, supported by a thesis that explains the method, experiments, limitations, and practical implications.

## #72 Research and Implementation of Emotion Recognition System of Forum Text Based on LLM

I would like to apply for this project because it is the closest match to my current interest in large language model applications and text understanding. I am studying Electronic Information Engineering, but my academic and career direction has moved toward applied AI, machine learning, and LLM-based systems. A forum text emotion recognition system based on LLM would allow me to combine natural language processing, model evaluation, software implementation, and a practical application scenario.

Forum text differs from formal writing. Users may write short replies, slang, incomplete sentences, sarcasm, mixed emotions, or comments that depend on surrounding context. Traditional sentiment analysis often reduces text into positive, negative, or neutral labels, but online discussions can express anger, anxiety, disappointment, excitement, trust, confusion, or several emotions at once. I am interested in this project because LLMs can support richer analysis. They can classify emotion, explain the reason behind a prediction, interpret context, and summarise emotional trends across a discussion.

My background gives me a suitable starting point. I have studied Artificial Intelligence and Machine Learning and have experience with Python and PyTorch. My NeRF project introduced me to neural model implementation and the process of learning hidden structure from data. My NIPT statistical modelling project trained me to handle real data, choose metrics with care, and connect modelling results with a practical decision problem. My SVD image compression project strengthened my understanding of representation and information reduction. These projects differ from text emotion recognition, but they share the same core process: define the problem, prepare data, build models, evaluate results, and explain limitations.

For this project, I would like to avoid a shallow sentiment-classification demo. A stronger version of the project could include data preprocessing, emotion taxonomy design, baseline models, LLM-based classification, explanation generation, and a simple interface for analysing forum text. I would first build a baseline using traditional machine learning or smaller neural models, then compare it with LLM-based approaches. Depending on the requirements, I could use prompt engineering, few-shot examples, open-source LLMs, or a hybrid pipeline where a conventional classifier provides stable predictions and an LLM provides explanations or summaries.

Evaluation would be central to the project. LLM responses can sound convincing even when they are wrong, so I would use labelled data if available and evaluate classification performance with accuracy, macro-F1, confusion matrices, and category-level analysis. For explanation quality, I would analyse typical examples and failure cases. If the dataset contains ambiguous emotional expressions, I would discuss uncertainty rather than forcing every example into a confident label. This would make the thesis more rigorous.

I would also design the system as a practical tool. A useful forum emotion recognition system should include a data pipeline, a model layer, and a result display layer. The data pipeline would handle text cleaning, anonymisation if needed, segmentation, and label preparation. The model layer would include baseline and LLM-based methods. The result display layer could show emotion distribution, representative examples, confidence or uncertainty, and short explanations. If time allows, I could add a function that summarises emotional trends by topic or time period.

This project fits my future plan to work in AI engineering, machine learning engineering, or LLM application engineering. It would let me build experience in NLP, LLM integration, evaluation, and application design. Compared with hardware-heavy topics, it is better aligned with my current strengths and would allow me to focus on AI modelling and software implementation.

If selected, I would clarify the target forum domain, language, emotion categories, and expected dataset. Then I would implement data cleaning, baseline classification, LLM-based classification, and a simple system interface. My final goal would be a functioning emotion recognition system and a thesis that explains the model choices, evaluation results, and practical meaning of the system.

Edge AI offers a different approach. If a learning assistant can run part of its intelligence on an Ascend development board, it may respond faster, protect data better, and remain useful when the network is unstable. This direction interests me because it turns AI from a remote service into a deployable system.

My academic background makes the topic suitable for me. I have studied Artificial Intelligence and Machine Learning, Signals and Systems, Digital Logic, Circuit Analysis, Linear Algebra, and Calculus. My NeRF-based 3D reconstruction project helped me understand neural model implementation and training. My NIPT statistical modelling project trained me to work with real data and evaluate models with care. My autonomous line-following robot car project gave me experience with sensors, control logic, and practical system integration. Although this project does not ask me to design a PCB, it can still benefit from my ability to connect software, AI models, and hardware-related constraints.

For this project, I would like to build a learning assistant with a clear scope. Possible functions include course-material question answering, learning resource retrieval, personalised review suggestions, quiz generation, and mistake explanation. The system should support a learning workflow rather than behave as a generic chatbot. For example, a student could ask questions about course content, receive answers grounded in local materials, complete a short quiz, and receive recommendations based on weak areas. I am also interested in the engineering discipline required by edge deployment. This topic fits my career direction in AI engineering, LLM application engineering, and intelligent systems. A learning assistant deployed on Ascend would show that I can work with AI models and practical deployment environments. Many future AI applications will require local inference or hybrid cloud-edge architectures, so the skills from this project would be valuable beyond the final-year project itself.

If selected, I would first study the Ascend development environment and confirm the deployment constraints. Then I would define the learning-assistant functions, build a software baseline, move suitable components to the board, and evaluate the deployment choices. My goal would be a clear demo, measurable results, and a thesis that connects AI workflow design with edge deployment.

## #74 / #2 AI-Powered Multi-Course Homework Management and Intelligent Grading Assistant System Based on openEuler & Ascend

I would like to apply for this project because it is a practical AI application system with a clear educational scenario. The project focuses on a multi-course homework management and intelligent grading assistant system based on openEuler and Ascend. It combines software engineering, database design, AI-assisted evaluation, and deployment on a domestic computing platform. This fits my current direction in applied AI and intelligent systems.

The problem addressed by the project is familiar in university teaching. Students often take several courses at the same time, while teachers and teaching assistants need to manage assignments, submissions, deadlines, records, and feedback. Traditional submission methods can become scattered across forms, files, emails, or paper documents. This creates missed submissions, inefficient checking, inconsistent feedback, and difficulty tracking student progress across courses. An AI-powered homework management and grading assistant can improve this workflow by organising submissions, supporting preliminary grading, generating feedback, and helping teachers identify common learning problems.

My background prepares me for this project. I have studied Artificial Intelligence and Machine Learning, Linear Algebra, Calculus, Signals and Systems, Digital Logic, and Circuit Analysis. I have programming experience in Python, C, and C++, and I have used PyTorch in AI-related projects. In my NIPT statistical modelling project, I worked with real data, built models, and used evaluation metrics to support decision-making. In my SVD image compression project, I implemented a data-processing pipeline and analysed the relationship between representation and output quality. In my autonomous robot car project, I gained experience in integrating different system components. These experiences are relevant because this project requires both AI logic and a working software system.

For this project, I would like to build a system with clear user roles and functions. Students could submit assignments, view deadlines, and receive feedback. Teachers could create assignments, manage course groups, check submission status, and review AI-generated grading suggestions. The AI assistant could help with objective questions, short-answer assessment, programming assignment feedback, rubric-based grading, or learning analytics, depending on the expected scope. The system could also generate statistics such as submission rates, common mistakes, grade distributions, and course-level learning trends.

I understand that this project could become too similar to a normal management system if the AI component is weak. I would therefore focus on making the grading assistant meaningful. For example, I could design a rubric-based workflow where the AI provides a preliminary score and explanation, while the teacher keeps final control. I could compare AI suggestions with reference answers or teacher-provided samples and analyse cases where the AI gives unreliable feedback, with special attention to open-ended answers. This would make the project more rigorous and prevent it from becoming only a CRUD system.

I would also pay attention to fairness and human control in the grading workflow. AI-generated feedback can save time, but teachers should still inspect, edit, accept, or reject its suggestions. The system should keep grading records and make the reasoning behind each suggestion visible enough for review. This would make the project more responsible and more realistic.

The openEuler and Ascend components make the project more distinctive. If the project requires deployment on openEuler or use of Ascend AI capabilities, I would treat this as part of the engineering contribution. I would learn the required environment, test deployment procedures, and document the system architecture. If full model deployment on Ascend is required, I would consider lightweight models or modular design. If Ascend supports platform demonstration, I would focus on system stability and reproducibility.

This project matches my goal of working in AI engineering or LLM application development. It would allow me to demonstrate software development, AI integration, database design, deployment, and evaluation. The problem is concrete, the users are clear, and the system can be tested through realistic teaching scenarios.

If selected, I would clarify the course types, assignment formats, grading functions, and deployment environment. Then I would design the database and user workflow, build the homework management system, add the AI grading module, evaluate it with sample assignments, and test the system on the required platform. My goal would be a practical, measurable final-year project aligned with my future direction.
