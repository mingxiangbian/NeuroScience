# IELTS 事件触发式结算系统

本项目不按固定周数、每日打卡或学习时长推进。学习只在真实证据出现后开启一个单元，并以可复查产物结算。

## 当前边界

- 运营目标：Overall 7.5。
- 单项最低线：尚未确认，不作推断。
- 同时最多一个活动单元。
- 队列只是候选，不代表欠下的任务。
- 网页只展示 repo 中的状态；正式结算通过与助手的对话完成，再写回 source of truth。
- 诊断、模考和明确要求限时的样本保留计时；普通修复单元不按时长结算。

## 学习循环

```text
真实输出
  -> 评分与错误信号
  -> 选择一个最高价值问题
  -> 开启一个学习单元
  -> 修订或新样本验证
  -> 按判据结算
  -> 更新错误、成绩证据与下一触发器
```

## 四类单元

| 类型 | 用途 | 必须留下的产物 | 结算判据 |
| --- | --- | --- | --- |
| diagnostic | 获取缺失的能力证据 | 限时样本、录音或完整题组，以及评分记录 | 样本可定位；评分维度和置信度已记录；至少产生一个可行动判断 |
| repair | 修复一个高影响错误机制 | 原样本、修订版和差异说明 | 能解释错误机制；修订版消除该错误；写明下一次独立新样本验证条件 |
| mock | 验证整场考试执行能力 | 完整限时结果和复盘 | 时间、分项表现、失分原因与考试决策都有证据 |
| calibration | 新证据改变目标、排序或考试决策 | 一条决策记录 | 写清什么证据改变了什么决定，并更新单元或目标 |

## 错误状态

- `active`：真实样本已证明错误存在。
- `improving`：完成过一次有证据的修订，并能解释错误机制。
- `fixed`：连续 3 个独立新样本未再出现同类错误。
- `regressed`：改善或修复后复发；连续无错计数清零。

仅修好旧答案不能把错误标为 `fixed`。

## 事件触发器

系统只在以下事件出现时重新校准：基线证据完成、高影响错误集合变化、两次可比模考可用、错误复发、外部硬期限改变或目标稳定达到。事件状态记录在 `calibration-events.json`，不绑定 Week 2/4/6/8。
