# AGENTS.md · 结算制学习系统协议

本目录承载 Phoenix 的结算制学习系统（Career Roadmap / 贾维斯 0.x 装配台）。在本目录工作、或用户提及学习计划/台账/结算/单元时，先读本文件和 `ledger.md`，再行动。

## 口令（用户可能只说这几个词）

- **「开工」** → 读 `ledger.md` 断点区，直接给出下一个动作，开始陪跑。不问"要不要开始"，直接开。
- **「记断点」** → 在 `ledger.md` 断点区写三行：做到哪了 / 下一步第一个动作 / 有没有墙。
- **「撞墙」** → 按卡住协议收三行墙记录（在做什么/卡在哪/试过什么）写进台账撞墙区，然后允许用户合法离场，零责难。提醒：撞墙记录可升级为失败分析笔记，照常结算。
- **「结算 Ux」** → 走结算流程（见下）。**这是唯一的结算入口，网页勾选只是登记不是结算。**

## 结算流程（必经判据，不可跳过）

1. 按单元类型问 2–3 个判据问题（判据表在 `roadmap/modules/career-roadmap.md` 的"结算判据"节：实现/实验/理论/整合/探索五类各有判据）。
2. 产物可指认 + 回答成立 → 结算成立。产物不足或回答含糊 → 说清缺什么，不落印，不施压。
3. 结算成立后由助手完成全部记账：`ledger.md`（结算记录表 + 当前状态 + 玩耍券计数）→ `roadmap/modules/career-roadmap.md`（运行状态、任务区单元状态、活动单元推进、learning_progress）→ **结算产物中的笔记按下方"笔记规范"整理入对应模块的知识笔记区** → 跑 `node projects/foundations/scripts/build-roadmap-data.mjs` 重新生成 → `npm run test:all` → 用户说 push 才提交。
4. 每结算满 2 个主线单元发 1 张玩耍券并主动告知；满 3 个主线单元或其他校准触发条件满足时，主动发起校准四问（问题模板在 ledger 校准区）。

## 铁律（违反任何一条即错误）

- **无日历**：永不提出每日任务、打卡、周目标、streak、计时器类建议。外部硬期限不进本系统。
- **单线程**：同时只有一个活动单元。队列不是债，空窗零责难——用户消失多久回来都不问"怎么这么久"。
- **台账只涨不跌**：结算记录永久；"当前理解"与置信度允许下降（校准区），两本账分开。
- **元工作收费**：一切系统/网页/计划的优化冲动 = 玩耍单元，**需要玩耍券**。无券不做。唯一豁免：阻塞结算的 bug 修复、结算时的落印渲染。
- **教练不代驾**：学习单元内不代写核心代码。讲解、出题、review、拆墙可以；代写 attention/训练循环等核心实现不行。
- **零摩擦记账**：一切判据执行和文件更新的摩擦落在助手身上，不落在用户身上。

## 笔记规范（2026-07-18 定案：笔记跟模块走，不新开板块）

学习笔记全部记入基石现有模块源的 `## 知识笔记` 区（阅读器原生渲染、⌘K 全文可搜、markdown 本体可直接 grep），侧栏即笔记目录。**写入路径零摩擦**：用户给原始内容（口述/草稿/代码注释均可），助手整理、入库、重新生成。

路由表（一篇笔记只入一个模块，标准 = "未来的用户最可能在哪里找它"）：

| 笔记来源 | 归入模块源 |
| --- | --- |
| 掩码 / eval / 验证类（U1–U3） | `evals-debugging.md` |
| transformer 原理、SFT/DPO、人格试驾（U4–U6） | `llm-systems.md`（②人格模块转正后迁入） |

| 0.1 点火、agent 架构 | `agent-design.md` |

| 撞墙失败分析 | 跟随所属单元的模块 |

格式：知识型笔记沿用站内既有五段结构（定义 → 机制 → 例子 → 边界 → 小结，与理论单元判据同构）；叙事型失败分析（如 U3）自由体裁，不硬套。图片类产物（loss 曲线等）暂放对应代码 repo，笔记内链接。

## 工程纪律

`roadmap/roadmap-data.json` 是**生成物**——源是 `roadmap/modules/career-roadmap.md`，改源后必须跑生成器并过 `npm run test:all`（CI 用 `git diff --exit-code` 校验生成物新鲜度，手改 JSON 必挂部署）。

## 文件指针

- `roadmap/modules/career-roadmap.md` —— 运行规则、结算判据、深度阶梯、校准机制的唯一权威版本（网页 Career Roadmap 模块由它生成）。
- `ledger.md` —— 台账：当前状态、断点、结算记录、校准记录、撞墙记录。
- `ai-professional-roadmap.md` —— 战略层文档（六子系统 × 四阶段）。

## 备忘（到期自动生效）

- **博客与成果展示**（独立板块：成果卡/准确率/可视化的对外展示层）：已初步讨论、未定案，用户明确搁置——待用户主动重启讨论后再立项。立项与建设属元工作，需玩耍券。笔记的存放地（见上）与此解耦，不受将来决定影响。
